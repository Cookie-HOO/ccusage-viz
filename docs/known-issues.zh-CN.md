# 已知问题

[English](known-issues.md)

本页记录受支持的 `ccusage-viz` 与 `ccusage` 组合中已知的行为。相关上游行为变化后，应更新或移除对应条目。

## Dashboard 运行一段时间后可能失去响应

### 症状与范围

Dashboard 运行一段时间后，键盘输入和刷新可能停止响应。此时可能需要关闭终端并重新打开，
Dashboard 才能恢复使用。

### 恢复方式

关闭受影响的终端，重新打开终端会话，再次启动 Dashboard。若方便，请记录运行时长、Dashboard
布局、刷新或采样间隔，以及重新打开前能够获取的脱敏输出。

## Monitor 当前观测值可能暂时消失，之后恢复

### 症状与范围

Monitor 根据连续累计采样值中相互兼容的一对样本计算当前吞吐量。首次采样、暂停后恢复、长时间调度或休眠间隔、
Monitor 范围变化，或遇到无效/重置的采样区间后，当前观测值或排名可能暂时显示为空。之后获得兼容的采样对时，
观测值可能恢复。

### 这意味着什么

这是为了避免跨越未观测时间或不同数据范围时生成误导性的速率。Monitor 会先建立新的基线，等到后续兼容采样后
才重新显示当前值。仍然兼容的历史记录可能保留，但不表示所有历史桶都会无限期保留。

### 恢复方式

等待足够的定时采样，以便先建立基线，再获得后续兼容采样。在交互式视图中可按 `r` 请求手动刷新。
确认 `ccusage` 和来源 Agent 正常运行。只有在后续采样后仍未恢复时，才考虑重启 Monitor 或 Dashboard。

### 安全地报告问题

如果问题持续存在，请附上 `ccusage-viz` 和 `ccusage` 版本、操作系统、命令形态、采样间隔、观测值是否恢复，
以及仅经过脱敏的诊断信息。分享前请移除本地路径、用户名、token、cookie、账户数据和其他私有标识符。

## 间歇性的 `unified_daily` 本地 Agent 数据库访问失败

### 症状与范围

依赖 `unified_daily` 的图表、Dashboard Pane 和 Monitor 采样，偶尔可能因 `ccusage`
无法读取本地 Agent 数据库而失败。该问题不稳定复现；无需修改配置，之后的刷新也可能成功。

### 这意味着什么

拥有该数据库的 Agent 可能正在初始化、重启、升级、轮换数据，或持有数据库锁。在这些情况下，
`ccusage` 可能暂时无法打开或读取其本地数据库。

这是上游/本地状态的可用性问题，不能据此推断 `ccusage-viz` 创建或损坏了另一个用量数据库。

### 恢复方式

1. 等待下一次已配置的刷新，并检查是否成功。
2. 在交互式视图中按 `r` 请求手动刷新。
3. 确认拥有该本地数据库的 Agent 正常运行。
4. 若失败持续存在或可以稳定复现，更新 `ccusage` 与相关 Agent，再按下方信息反馈问题。

### 安全地报告问题

错误输出可能包含本机路径或其他私有诊断信息。提交 issue 前，请从 stderr 或日志中移除路径、用户名、
token、cookie、账户数据和其他私有标识符。

请附上 `ccusage-viz` 版本、`ccusage` 版本、操作系统、命令形态、后续重试是否成功，以及仅经过脱敏的
诊断输出。对于持续或可复现的问题，请使用[Bug 报告表单](https://github.com/Cookie-HOO/ccusage-viz/issues/new?template=bug_report.yml)。
