# ccusage-viz 0.3.0 Release Design

## Goal

Publish ccusage-viz 0.3.0 from the current development history, which is based on the online v0.2.2 release, through the repository's protected main-branch and GitHub Release workflow.

## Baseline and scope

- Release baseline: tag `v0.2.2` at commit `ca10dcc7`.
- Release candidate: the current committed HEAD, including all changes after `v0.2.2`.
- The release includes the committed Dataset V2 and managed Dataset workflows, source-owned historical and Monitor metrics, custom Ranking improvements, Dashboard preset and focused-chart unification work, CLI guidance, documentation, tests, and fixes.
- No new product feature will be added during release preparation.
- Release preparation may fix only issues required to pass release validation or make the published documentation/version metadata accurate.

## Version and documentation updates

Set the package and runtime version to `0.3.0` in:

- `pyproject.toml`
- `src/ccusage_viz/__init__.py`
- `uv.lock`, regenerated through uv

Update public release-facing documentation:

- Change README badges/copy that state the current version from `0.2.2` to `0.3.0`.
- Change both roadmap files to identify `0.3.0` as the current version and move future work out of language that describes 0.3.x as wholly unreleased.
- Add matching English and Chinese `0.3.0` sections to the versioning documents.

The release notes will emphasize:

1. Managed Dataset discovery, installation, registration, and execution.
2. The V2 multi-Metric protocol, source-owned values, historical Ranking, and custom Monitor support.
3. Rich Ranking grouping, filtering, descriptions, search, copy, scrolling, and rendering behavior.
4. Dashboard presets, Dataset-aware Pane workflows, and focused chart routes unified on the Dashboard runtime.
5. CLI diagnostics, terminal robustness, performance, documentation, and correctness fixes.

Compatibility notes will call out the new `ccuv chart KIND` command hierarchy and the Alpha-stage Dataset/protocol evolution where relevant.

## Validation

Run the same checks required by CI:

1. `uv sync --locked --all-groups`
2. `uv run ruff format --check .`
3. `uv run ruff check .`
4. `uv run ty check src/ccusage_viz`
5. `uv run pytest`
6. `uv build`
7. `uvx twine check dist/*`
8. Install the built wheel into an isolated virtual environment.
9. Smoke-test `ccusage-viz --version`, `ccusage-viz --help`, and the `ccuv` alias.

A failure blocks publication. Release-only failures may be corrected and the complete relevant validation rerun.

## Git and publication flow

1. Create/use branch `release/0.3.0` from the current clean HEAD.
2. Commit release metadata and documentation as a release preparation commit.
3. Push `release/0.3.0` to GitHub.
4. Open a pull request targeting `main` and wait for required checks.
5. Merge the pull request.
6. Confirm the merge commit on `main` contains version `0.3.0` and is descended from `v0.2.2`.
7. Publish a non-prerelease GitHub Release tagged `v0.3.0` at the merged main commit, with bilingual-aware concise release notes (primary notes in English with links to both versioning documents).
8. The existing `pypi-publish.yml` workflow builds from the tag and publishes via Trusted Publishing.
9. Verify the GitHub workflow succeeds and PyPI reports `ccusage-viz 0.3.0`.

Do not tag the feature branch: the publish workflow requires the tag commit to be an ancestor of `origin/main`.

## Failure handling

- If push or PR creation is blocked by authentication, stop with the exact command/output needed for the maintainer to continue.
- If CI fails, inspect the failing job, fix only release-relevant defects on `release/0.3.0`, push, and wait for checks again.
- If merging is blocked by repository policy, leave the passing PR ready for maintainer merge.
- If GitHub Release publication succeeds but PyPI publication fails, do not move or recreate the tag. Diagnose and rerun the failed workflow after correcting the publishing environment.
- Never overwrite the existing `v0.2.2` tag or publish `0.3.0` from a commit not on `main`.

## Success criteria

- The release PR is merged into `main` with required checks passing.
- GitHub has a non-prerelease `v0.3.0` Release at the merged commit.
- The PyPI publish workflow succeeds.
- `https://pypi.org/project/ccusage-viz/` exposes version `0.3.0`.
- Installing the published package reports `ccusage-viz 0.3.0` for both installed command aliases.
